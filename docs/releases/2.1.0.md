# Agentic Spring AI 2.1.0

Agentic Spring AI 2.1.0 is the first stabilization release after the 2.0 fork.
It strengthens runtime boundaries, fixes graph and checkpoint correctness edge
cases, and establishes a reproducible Core/Extensions compatibility baseline.

## Highlights

- Studio APIs are token-protected while static UI assets remain public.
- HTTP, document, filesystem, and code-execution paths use restrictive defaults.
- Docker execution has bounded resources and a writable `/tmp` tmpfs under a
  read-only root filesystem.
- Observation content capture is opt-in, redacted, and truncated.
- Nacos MCP callback lifecycle, timeout, and logging behavior is hardened.
- A2A execution uses a bounded executor with documented backpressure behavior.
- Provider-neutral model and document parsing contracts are published from
  Extensions as `agentic-spring-ai-extensions-model`; the unpublished Core
  development artifact was removed.
- AgentScope, A2A Nacos, agent configuration Nacos, and Sandbox artifacts are
  maintained in the Extensions repository without changing Maven coordinates.
- JDBC, Redis, and MongoDB graph persistence are available as new Extensions
  artifacts with Core compatibility APIs; the Docker code executor is available
  only from Extensions.
- RAG retrieval, HTTP, and document extraction graph nodes are available as new
  Extensions artifacts; their old Core classes have been removed.

## Correctness Fixes

- FileSystemSaver treats thread IDs containing regex metacharacters literally.
- MongoSaver applies configured checkpoint retention to repeated same-thread writes.
- Resumed graph nodes receive the state stored in the checkpoint.
- Parent graphs merge only the state delta produced by child graphs.
- Parallel child-graph outputs are preserved.
- ReactAgent consumes one-shot `jump_to` routing state instead of leaking it to
  later loops.
- Dynamic grouped tools remain visible after agent construction.

## Compatibility

- Java 17 and Java 21 are verified.
- Spring Boot 4.1.1 and Spring AI 2.0.1 are the dependency baseline.
- Core and Extensions `2.1.0` release dry-runs produce binary, source, and
  javadoc artifacts.
- Core full tests pass against source-built Extensions `2.1.0-dev` artifacts.
- The model contract artifact preserves its Java packages and public API while
  moving to the Extensions-owned Maven coordinate.
- Legacy Core and new Extensions persistence/executor implementations pass
  bidirectional compatibility tests.
- Migration parity tests verified the Extensions graph node API shape and
  behavior before the old Core implementations were removed, including RAG
  retrieval/rerank outputs, HTTP request mapping, document parsing, timeouts,
  and private-network blocking defaults.
- New Extensions graph node artifacts are plain libraries; adding them does not
  auto-configure, component-scan, or automatically register graph nodes.

See [the migration guide](../2.1.0-migration.md) for security-default changes,
storage compatibility, source-build verification, and rollback guidance.

## Deferred Work

Unreproduced issues are tracked in the GitHub `2.2.0` milestone. No public
Extensions Parser, Reader, or Tool Calling artifact is removed in 2.1.0; those
families require usage evidence, replacements, and a deprecation period before
any later removal.
