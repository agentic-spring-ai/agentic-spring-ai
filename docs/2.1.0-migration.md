# 2.1.0 Migration and Compatibility Guide

This guide covers the upgrade from the `2.0.0.0` line to `2.1.0`.
The current development coordinate is `2.1.0-dev`; it is not a Maven Central
release. Use the source-build verification command below until the release
artifacts are published.

## Version Baseline

| Component | 2.1.0 baseline |
| --- | --- |
| Java | 17 and 21 verified; 17 or newer is required |
| Spring Boot | 4.1.1 |
| Spring AI | 2.0.1 |
| Core | 2.1.0-dev |
| Extensions | 2.1.0-dev |

## Module Ownership

Core no longer imports the Extensions BOM. Applications that use optional
integrations should import both BOMs: `agentic-spring-ai-bom` for the graph,
agent, model, Studio, and built-in node modules, and
`agentic-spring-ai-extensions-bom` for provider and infrastructure adapters.

The following artifacts keep their existing Maven coordinates but are now
version-managed and released by Extensions:

- `agentic-spring-ai-starter-agentscope`
- `agentic-spring-ai-starter-a2a-nacos`
- `agentic-spring-ai-starter-config-nacos`
- `agentic-spring-ai-sandbox`

The following provider-specific implementations are introduced as new
Extensions `2.1.0` artifacts:

- `agentic-spring-ai-graph-persistence-jdbc`
- `agentic-spring-ai-graph-persistence-redis`
- `agentic-spring-ai-graph-persistence-mongodb`
- `agentic-spring-ai-code-executor-docker`

The old Core database implementations remain available but are deprecated since
2.1.0. The old Core `DockerCodeExecutor` has been removed; applications must use
the Extensions artifact. The new artifacts require explicit construction and do
not auto-configure savers, stores, or executors. See
[the persistence and executor migration guide](persistence-executor-migration.md)
for package mappings and rollback guarantees.

Provider-neutral rerank contracts and the document parser SPI now live in the
Extensions-owned `agentic-spring-ai-extensions-model` artifact. The unpublished
development coordinate `agentic-spring-ai-model` was removed. Existing Java
package names are unchanged. Import `agentic-spring-ai-extensions-bom` to manage
the replacement artifact. Markdown, HTML, YAML, and Tika parsers are discovered
from their Extensions artifacts through `ServiceLoader`.

## Graph Node Migration

The RAG retrieval, HTTP, and document extraction graph nodes are provided as new
Extensions `2.1.0` artifacts. Their old Core classes have been removed from
`agentic-spring-ai-starter-builtin-nodes`.

| 2.0 Core class | 2.1 Extensions replacement | Artifact |
| --- | --- | --- |
| `io.github.agentic.spring.ai.graph.node.KnowledgeRetrievalNode` | `io.github.agentic.spring.ai.graph.node.rag.KnowledgeRetrievalNode` | `agentic-spring-ai-graph-node-rag` |
| `io.github.agentic.spring.ai.graph.node.HttpNode` | `io.github.agentic.spring.ai.graph.node.network.HttpNode` | `agentic-spring-ai-graph-node-network` |
| `io.github.agentic.spring.ai.graph.node.DocumentExtractorNode` | `io.github.agentic.spring.ai.graph.node.network.DocumentExtractorNode` | `agentic-spring-ai-graph-node-network` |

Import `agentic-spring-ai-extensions-bom`, add the replacement artifact, and
change imports to the new package. The replacement artifacts preserve the Core
constructors, builders, state keys, defaults, output shapes, timeout behavior,
document parser discovery, and private-network blocking defaults.

The replacement artifacts are plain libraries. They do not add Spring Boot
auto-configuration, component scanning, `ServiceLoader` graph-node discovery, or
automatic node beans. Applications must continue to construct and register graph
nodes explicitly.

Release Core `2.1.0` first, then release Extensions `2.1.0` against that exact
Core version. The removed Core imports are not a rollback path; applications
must use the Extensions artifacts.

## Security Defaults

Applications upgrading to 2.1.0 should review these intentional default changes:

- Studio APIs require `spring.ai.alibaba.agent.studio.execution.auth-token` and
  the `X-Agentic-Studio-Token` header. Static UI files remain public.
- HTTP and document fetches reject private, loopback, link-local, and metadata
  addresses by default. Enable private access only for a trusted endpoint.
- Local document paths must be inside the configured document root.
- Docker execution disables networking, uses a read-only root filesystem, and
  applies CPU, memory, swap, PID, capability, and output limits. `/tmp` remains
  a 64 MiB writable tmpfs when the root filesystem is read-only.
- Local code execution uses an isolated temporary directory per invocation;
  multiple blocks in one invocation still share that directory.
- Graph observation prompt/completion content capture is disabled by default.
  Set `spring.ai.alibaba.graph.observation.capture-content=true` only when raw
  content may be recorded.

## Storage Compatibility

`FileSystemStore` now treats namespace values and keys as single safe path
segments. Do not encode hierarchy with `/`, absolute paths, `.` or `..` inside
one value. Split hierarchy across multiple namespace elements before upgrading.

Existing Redis data is not rewritten automatically. Keep the configured store
key prefix stable, and plan any legacy `spring:ai:alibaba:store:` migration
before switching prefixes.

## A2A Executor

The A2A server uses a bounded executor. Configure
`spring.ai.alibaba.a2a.server.executor-core-pool-size`,
`spring.ai.alibaba.a2a.server.executor-max-pool-size`, and
`spring.ai.alibaba.a2a.server.executor-queue-capacity` for your traffic. Queue
saturation uses caller-runs backpressure, so request-thread latency can rise
under sustained overload.

## Reproducible Source Compatibility Check

The Extensions `2.1.0-dev` BOM is currently a source-development coordinate,
not a published artifact. Verify Core and Extensions in an isolated Maven local
repository instead of relying on an existing `~/.m2` cache:

```bash
tools/scripts/verify-extensions-compatibility.sh \
  /path/to/agentic-spring-ai-extensions
```

The source build installs Core before building Extensions. A successful run
proves source-level compatibility; it does not publish artifacts or replace the
release gates.

Publish Core `2.1.0` before Extensions `2.1.0`. The Extensions release must
resolve both `revision` and `agentic-spring-ai.version` to `2.1.0` so its
published POMs do not reference the development Core coordinate.

The CI compatibility job verifies Core compilation on JDK 17 and JDK 21. Spring
Boot `4.1.1` and Spring AI `2.0.1` remain the supported dependency baseline for
this release line.

## Upgrade and Rollback

1. Set the Studio token before accepting traffic after upgrading.
2. Review code-execution and document-fetch opt-ins in deployment config.
3. Run the full test/build checks and the isolated Extensions compatibility check.
4. Keep a backup of checkpoint/store data before changing store prefixes.
5. To roll back, restore the previous application artifact and configuration,
   then restore any store prefix changes made during the upgrade.
